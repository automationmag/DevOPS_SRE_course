# Лаборатория 12. Учебный инцидент

**Цель:** пройти все четыре фазы на настоящем (но учебном) падении, заполнить разбор и связать его с карточками.

**Время:** 40–60 минут.

**Нагрузка:** короткая остановка контейнера. Влезает в 1 ГБ.

**Перед стартом:** хорошо, если сделана лаборатория 11 — тогда обнаружение произойдёт само, через уведомление. Если нет, обнаружением будет ваша собственная проверка.

!!! info "Почему пожар учебный"
    Тренироваться в спокойный день полезнее, чем впервые проходить процедуру в три часа ночи. И стыда меньше: вы сами всё устроили.

## Фаза 1. Обнаружили

### Шаг 1. Зафиксировать исходное состояние

**Зачем:** нужна точка отсчёта.

**Где вводить:** терминал сервера (`ssh ucheb`)

```bash
date
cd /opt/pulse
docker compose -f compose.caddy.yml ps
```

**Что должно получиться:** текущее время и оба контейнера в состоянии `Up`. Запишите время.

### Шаг 2. Устроить падение

**Где вводить:** терминал сервера

```bash
docker compose -f compose.caddy.yml stop pulse
date
```

Запишите время начала инцидента.

**Что должно получиться:** контейнер остановлен.

### Шаг 3. Дождаться сигнала

**Зачем:** увидеть, как выглядит обнаружение. Не чините сразу — на это и отводится фаза.

Подождите до трёх минут.

**Что должно получиться:**

- если сделана лаборатория 11 — сообщение в Telegram;
- если нет — проверьте сами:

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://pulse.ваш-домен.ru/health
```

**Что должно получиться:** код `502`, то есть вахтёр жив, а приложение за ним — нет.

## Фаза 2. Сдержали

### Шаг 4. Не сделать хуже

**Зачем:** это самая недооценённая фаза. Большинство серьёзных потерь происходит именно здесь.

Откройте **одну** карточку — [сайт не открывается](../runbooks/site-down.md).

Чего сейчас делать нельзя:

- трогать файрвол;
- менять записи DNS;
- запускать обновление системы;
- удалять тома или чистить Docker;
- переустанавливать сервер.

**Что должно получиться:** вы прочитали карточку и знаете следующий шаг. Руки при этом ничего лишнего не сделали.

### Шаг 5. Проверить, что сервер в порядке

**Где вводить:** терминал сервера

```bash
free -h
df -h /
```

**Что должно получиться:** память и диск в норме. Значит, причина не в ресурсах, и чистить ничего не надо.

## Фаза 3. Починили

### Шаг 6. Определить слой

**Зачем:** лечить надо конкретный слой, а не всё подряд.

**Где вводить:** терминал сервера

```bash
docker compose -f compose.caddy.yml ps
docker compose -f compose.caddy.yml logs pulse --tail=20
```

**Что должно получиться:**

- состояние `Exited` — процесс не запущен;
- в логах нет ошибок, последние строки обычные.

**Вывод:** слой «процесс приложения», контейнер остановлен, причина внешняя — это сделали вы.

### Шаг 7. Вылечить

**Где вводить:** терминал сервера

```bash
docker compose -f compose.caddy.yml start pulse
sleep 3
curl -s https://pulse.ваш-домен.ru/health
date
```

**Что должно получиться:** ответ `{"status":"ok"}`. Запишите время окончания.

Проверьте, что данные на месте:

```bash
cat /opt/pulse/data/note.txt
```

**Что должно получиться:** ваша заметка. Останов контейнера данных не касается — важно убедиться в этом своими глазами.

### Шаг 8. Посчитать длительность

Вычтите время из шага 2 из времени шага 7.

**Что должно получиться:** число минут. Это то, что вы вычтете из бюджета в 432 минуты.

## Фаза 4. Записали

### Шаг 9. Заполнить разбор

**Где делать:** файл у себя или раздел инвентаря. Не в публичный репозиторий.

Заполните шаблон из [урока про разбор](../modules/m12/03-postmortem.md):

- когда началось и закончилось;
- сколько минут бюджета сожжено;
- что было видно снаружи;
- как узнали;
- что было на самом деле;
- почему система это допустила;
- что меняем.

**Что должно получиться:** одна страница. Ни слова про внимательность и характер.

### Шаг 10. Выбрать одно действие

Выберите **одно** и поставьте дату:

- включить проверку по расписанию, если ещё не сделано;
- добавить `docker compose ps` в еженедельный список;
- дописать ссылку на карточку в текст уведомления;
- поправить карточку, если она увела не туда.

**Что должно получиться:** действие с датой в календаре.

### Шаг 11. Сверить три карточки

**Где смотреть:** карточки курса:

- [сайт не открывается](../runbooks/site-down.md)
- [диск заполнен](../runbooks/disk-full.md)
- [сертификат истекает](../runbooks/ssl-expiring.md)

Для каждой ответьте: какой сигнал её вызывает и настроен ли он.

| Карточка | Сигнал | Настроен? |
|---|---|---|
| Сайт не открывается | проверка health | |
| Диск заполнен | занятость диска | |
| Сертификат истекает | срок сертификата | |

**Что должно получиться:** заполненная таблица. Пустые ячейки в третьей колонке — ваш список задач.

## Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| уведомление не пришло | проверка по расписанию не работает | `crontab -l`, смотрите `cron.log` |
| после запуска всё равно 502 | контейнер не поднялся | `docker compose logs pulse --tail=50` |
| заметка пропала | права на папку данных | `sudo chown -R 10001:10001 /opt/pulse/data` |
| не помните время начала | не записали сразу | в следующий раз записывайте первым делом |

## Готово, если

- [ ] Записаны время начала и окончания
- [ ] Слой назван словами, а не догадкой
- [ ] На фазе сдерживания не сделано ничего лишнего
- [ ] Данные пережили инцидент
- [ ] Разбор заполнен и умещается на страницу
- [ ] Есть одно конкретное действие с датой
- [ ] Цель и бюджет записаны в инвентарь
