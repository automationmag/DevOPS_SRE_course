# Лаборатория 1. Первый вход на сервер

**Цель:** завести рабочего пользователя `deploy`, настроить вход по ключу и закрыть вход по паролю.

**Время:** 40–70 минут. Не торопитесь на шаге 6.

**Нагрузка:** влезает в 1 ГБ.

## Перед стартом

Приготовьте:

- адрес сервера;
- пароль root из письма хостера;
- открытую вкладку панели хостера (там кнопка аварийной консоли);
- прочитанные уроки [про SSH](../modules/m01/03-ssh-kluchi.md) и [про Linux](../modules/m01/04-linux-minimum.md).

!!! warning "Главное правило этой лаборатории"
    Вы будете закрывать себе один способ входа и открывать другой. **Не закрывайте первое окно SSH**, пока не убедитесь, что новый вход работает во втором окне. Если что-то пойдёт не так, первое окно останется вашим спасением, а аварийная консоль в панели — запасным.

## Шаг 1. Публичный ключ на компьютере

**Зачем:** нам нужна строка, которую мы положим на сервер. Без неё вход по ключу не заработает.

**Где вводить:** PowerShell на вашем компьютере

```powershell
Get-Content $env:USERPROFILE\.ssh\id_ed25519_ucheb.pub
```

**Что должно получиться:** одна длинная строка, начинается с `ssh-ed25519`, заканчивается на `uchebnyy-vps`. Скопируйте её целиком.

Если файла нет — вернитесь к [уроку про ключи](../modules/m01/03-ssh-kluchi.md), шаг 2.

## Шаг 2. Вход под root

**Зачем:** пока у нас нет другого пользователя, создавать его может только root.

**Где вводить:** PowerShell на вашем компьютере

```powershell
ssh root@203.0.113.10
```

Подставьте свой адрес. Пароль при вводе не отображается — это нормально.

**Что должно получиться:** приглашение вида `root@vps-12345:~#`. Это **первое окно**, не закрывайте его до конца лаборатории.

## Шаг 3. Создать пользователя deploy

**Зачем:** чтобы не работать под root каждый день. Под обычным пользователем опасные команды не выполнятся случайно.

**Где вводить:** терминал сервера, первое окно

```bash
adduser deploy
```

Система попросит придумать пароль для нового пользователя — задайте и сохраните его в менеджере паролей, он понадобится для команд с `sudo`. Остальные поля (полное имя, телефон) можно пропустить клавишей Enter, в конце подтвердить `Y`.

**Что должно получиться:** строки `Adding user deploy...` и в конце `Is the information correct? [Y/n]`.

Теперь дадим ему право на административные команды:

```bash
usermod -aG sudo deploy
id deploy
```

**Что должно получиться:** вывод вида `uid=1000(deploy) gid=1000(deploy) groups=1000(deploy),27(sudo)`. Главное — наличие слова `sudo` в списке групп. Без него `deploy` не сможет ничего настраивать.

## Шаг 4. Положить ключ пользователю deploy

**Зачем:** сервер должен узнать вашу «замочную скважину», чтобы пускать без пароля.

**Где вводить:** терминал сервера, первое окно

```bash
mkdir -p /home/deploy/.ssh
nano /home/deploy/.ssh/authorized_keys
```

Откроется простой редактор. Вставьте публичную строку из шага 1 — одной строкой, без переносов. Затем:

- `Ctrl+O`, Enter — сохранить;
- `Ctrl+X` — выйти.

Теперь выставим права. SSH намеренно отказывается работать с ключами, доступными посторонним:

```bash
chown -R deploy:deploy /home/deploy/.ssh
chmod 700 /home/deploy/.ssh
chmod 600 /home/deploy/.ssh/authorized_keys
ls -l /home/deploy/.ssh
```

**Что должно получиться:** строка вида `-rw------- 1 deploy deploy ... authorized_keys`. Расшифровка: `-rw-------` означает доступ только владельцу, `deploy deploy` — владелец правильный.

## Шаг 5. Проверить новый вход, не закрывая старый

**Зачем:** это главная страховка лаборатории. Пока не убедимся, что вход по ключу работает, ничего закрывать нельзя.

Откройте **второе окно** PowerShell (первое оставьте как есть).

**Где вводить:** PowerShell на вашем компьютере, второе окно

```powershell
ssh -i $env:USERPROFILE\.ssh\id_ed25519_ucheb deploy@203.0.113.10
```

**Что должно получиться:** вход без запроса пароля от сервера и приглашение вида `deploy@vps-12345:~$`. Обратите внимание: в конце `$`, а не `#` — это признак обычного пользователя.

Если система просит passphrase — это пароль от вашего файла ключа, если вы его задавали. Это нормально.

Если вход не удался, **не трогайте настройки SSH**. Вернитесь в первое окно и проверьте содержимое `authorized_keys` и права из шага 4.

Проверим, что административные команды доступны:

```bash
sudo whoami
```

Система спросит пароль — **пароль пользователя deploy** из шага 3, не root.

**Что должно получиться:** слово `root`. Это значит, что `deploy` умеет временно повышать права.

## Шаг 6. Запретить вход по паролю

!!! danger "Выполнять только после успешного шага 5"
    Если вход по ключу ещё не работает, после этого шага вы потеряете доступ к серверу.

**Зачем:** чтобы автоматические переборщики паролей стучались в закрытую дверь.

**Где вводить:** терминал сервера, первое окно (там, где вы root)

```bash
nano /etc/ssh/sshd_config
```

Найдите три строки и приведите их к такому виду. Если перед строкой стоит символ `#`, его нужно убрать — это означает «строка отключена».

```
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
```

Сохраните: `Ctrl+O`, Enter, `Ctrl+X`.

Некоторые хостеры добавляют собственные настройки в отдельные файлы, которые перебивают основной. Проверим:

```bash
grep -R PasswordAuthentication /etc/ssh
```

**Что должно получиться:** список строк с указанием файлов. Если в каком-то файле из папки `/etc/ssh/sshd_config.d/` написано `PasswordAuthentication yes` — откройте его через `nano` и исправьте на `no`.

Применяем настройки:

```bash
systemctl restart ssh
```

**Что должно получиться:** команда отработает молча, без сообщений. Молчание здесь — признак успеха. Если увидите ошибку про `Unit ssh.service not found`, выполните `systemctl restart sshd`.

## Шаг 7. Проверить, что всё закрылось правильно

**Зачем:** убедиться, что нужный вход жив, а ненужный закрыт.

Откройте **третье окно** PowerShell.

**Где вводить:** PowerShell на вашем компьютере, третье окно

```powershell
ssh -i $env:USERPROFILE\.ssh\id_ed25519_ucheb deploy@203.0.113.10
```

**Что должно получиться:** вход работает, приглашение `deploy@...$`. Это обязательное условие — только теперь можно закрывать первое окно.

Теперь проверим, что старый способ действительно закрыт:

```powershell
ssh root@203.0.113.10
```

**Что должно получиться:** отказ `Permission denied (publickey)`. Это **успех**, а не ошибка: сервер больше не принимает пароли.

## Шаг 8. Короткая команда для входа

**Зачем:** чтобы не писать длинную строку с ключом каждый раз.

**Где вводить:** PowerShell на вашем компьютере

```powershell
notepad $env:USERPROFILE\.ssh\config
```

Блокнот предложит создать файл — согласитесь. Вставьте текст, подставив свой адрес:

```
Host ucheb
    HostName 203.0.113.10
    User deploy
    IdentityFile ~/.ssh/id_ed25519_ucheb
```

Сохраните и закройте. Проверяем:

```powershell
ssh ucheb
```

**Что должно получиться:** тот же вход, что и раньше, но команда теперь короткая. Дальше в курсе я буду писать именно `ssh ucheb`.

## Шаг 9. Включить swap

**Зачем:** на сервере с 1 ГБ памяти swap не даёт системе зависнуть при всплеске нагрузки.

**Где вводить:** терминал сервера

Команды и объяснение — на [странице про учебный VPS](../lab-server.md).

Проверка:

```bash
free -h
```

**Что должно получиться:** в строке `Swap` не `0B`, а размер, который вы задали, например `2,0Gi`.

## Если что-то пошло не так

| Симптом | Причина и решение |
|---|---|
| Вход по ключу не работает | В `authorized_keys` попал приватный ключ вместо публичного, или строка разбилась на несколько. Проверьте файл в первом окне. |
| `Permission denied`, хотя ключ правильный | Не выставлены права из шага 4. SSH отказывается работать с доступными всем ключами. |
| Отвалились от сервера совсем | Заходите через VNC-консоль в панели хостера под root с паролем — консоль не зависит от настроек SSH. Затем верните `PasswordAuthentication yes` и разбирайтесь. |
| Настройки не применяются | Их перебивает файл из `/etc/ssh/sshd_config.d/`. Ищите командой `grep` из шага 6. |

## Готово, если

- [ ] `ssh ucheb` пускает без пароля от сервера
- [ ] `sudo whoami` отвечает `root`
- [ ] `ssh root@адрес` отказывает с `Permission denied`
- [ ] В строке `Swap` не ноль
- [ ] В инвентарь записаны адрес, имя пользователя и путь к ключу
