# Лаборатория 8. Pages и идея деплоя по пушу

**Цель:** опубликовать учебник роботом на GitHub Pages и разобрать схему автоматической выкладки «Пульса», не включая её.

**Время:** 40–60 минут.

**Нагрузка:** сервер не задействован вовсе. Сборка идёт на машинах GitHub.

**Перед стартом:** сделан первый коммит по уроку 1 модуля 8.

!!! info "Что делать, если репозитория на GitHub ещё нет"
    Лаборатория засчитывается после шагов 1 и 7. Публикацию отложите, но сборку и разбор примера сделайте обязательно.

## Шаг 1. Проверить сборку у себя

**Зачем:** робот выполнит ту же команду. Ошибку дешевле найти на своём компьютере, чем в журнале автоматики.

**Где вводить:** PowerShell на вашем компьютере, в папке курса

```powershell
.\.venv\Scripts\Activate.ps1
mkdocs build --strict
```

**Что должно получиться:** строка `Documentation built in ... seconds` и ни одного предупреждения. Появилась папка `site` — её в репозиторий не добавляют.

Если сборка падает, в сообщении будет указан файл и причина — чаще всего битая ссылка. Почините и повторите.

## Шаг 2. Убедиться, что в репозитории нет секретов

**Зачем:** это последний момент, когда проверка стоит одну минуту. После публикации файлы увидят посторонние.

**Где вводить:** PowerShell на вашем компьютере

```powershell
git status --short
git ls-files | Select-String -Pattern "\.env$|id_ed25519|\.pem$"
```

**Что должно получиться:** вторая команда не находит ничего. Если что-то нашлось — не публикуйте, сначала уберите файл из отслеживания и смените засветившиеся ключи.

## Шаг 3. Создать репозиторий на GitHub

**Где делать:** сайт GitHub, кнопка **New repository**.

Что выбрать:

- имя — например `DevOPS_SRE_course`;
- видимость — публичный, если хотите бесплатные Pages;
- не добавлять README и `.gitignore`, они у вас уже есть.

**Где вводить:** PowerShell на вашем компьютере (подставьте свой логин)

```powershell
git remote add origin https://github.com/ВАШ_ЛОГИН/DevOPS_SRE_course.git
git branch -M main
git push -u origin main
```

**Что должно получиться:** строки о передаче объектов и в конце `branch 'main' set up to track 'origin/main'`.

Откройте репозиторий в браузере и посмотрите список файлов глазами. Файлов `.env` там быть не должно.

## Шаг 4. Указать адрес публикации

**Где смотреть:** файл `mkdocs.yml`, поле `site_url`.

Впишите:

```
site_url: https://ВАШ_ЛОГИН.github.io/DevOPS_SRE_course/
```

**Что должно получиться:** адрес заканчивается косой чертой. Если её не будет, оформление сайта сломается.

## Шаг 5. Добавить описание робота

**Где вводить:** PowerShell на вашем компьютере, в папке курса

```powershell
mkdir -Force .github\workflows
copy .\labs\ci\pages.yml .github\workflows\pages.yml
git add mkdocs.yml .github
git commit -m "Добавляет автоматическую публикацию учебника на Pages"
git push
```

**Что должно получиться:** коммит отправлен. На сайте GitHub в репозитории появилась папка `.github/workflows`.

## Шаг 6. Включить публикацию и дождаться результата

**Где делать:** репозиторий на GitHub → **Settings → Pages → Source** → выбрать **GitHub Actions**.

Затем откройте вкладку **Actions**.

**Что должно получиться:**

- в списке появился запуск с именем вашего коммита;
- сначала жёлтый кружок (выполняется), через пару минут зелёная галочка;
- при нажатии видны те же четыре шага, что вы читали в уроке.

Откройте адрес из шага 4.

**Что должно получиться:** учебник открывается в браузере с нормальным оформлением и работающим поиском.

Если запуск красный, нажмите на него и прочитайте шаг, на котором он упал. Чаще всего это та же ошибка, что показала бы локальная сборка из шага 1.

## Шаг 7. Разобрать выкладку «Пульса» на бумаге

**Зачем:** понять схему до того, как включать. Этот робот, в отличие от первого, ходит на ваш сервер.

**Где смотреть:** файл `labs/ci/deploy-pulse.example.yml` в папке курса.

Выпишите ответы на четыре вопроса:

1. Какие секреты нужны роботу и что означает каждый?
2. Почему для робота заводят отдельный ключ, а не используют личный?
3. Почему папка `data` не приходит из репозитория — и почему это хорошо?
4. Как вы откатитесь, если робот выложит плохую версию?

**Что должно получиться:** четыре ответа своими словами в инвентаре. Если на какой-то ответа нет — перечитайте [урок про секреты](../modules/m08/03-actions-i-sekrety.md).

!!! warning "Включать этого робота сейчас не нужно"
    Ручное копирование из модулей 3–5 остаётся законным способом. Автоматику подключают, когда ручной путь стал полностью предсказуемым.

## Шаг 8. Потренировать откат учебника

**Зачем:** увидеть, что откат — обычное действие, а не аварийная процедура.

**Где делать:** вкладка **Actions** в репозитории.

Откройте любой прошлый успешный запуск и нажмите **Re-run all jobs**.

**Что должно получиться:** новый запуск с тем же результатом. Именно так вы вернёте прошлую версию учебника, если новая окажется сломанной.

## Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| сайт открылся без оформления | `site_url` не совпадает с адресом Pages | сверьте адрес в Settings → Pages |
| запуск красный на шаге сборки | битая ссылка в текстах | воспроизведите локально `mkdocs build --strict` |
| вкладки Actions нет | описание лежит не в той папке | файл должен быть в `.github/workflows/` |
| Pages недоступны | репозиторий закрытый на бесплатном тарифе | сделайте публичным или отложите публикацию |
