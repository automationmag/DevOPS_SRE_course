# Лаборатория 5. Домен и замочек

**Цель:** открыть «Пульс» по адресу `https://ваше-имя` с замочком в браузере и закрыть прямой доступ по порту 8080.

**Время:** 40–90 минут плюс ожидание, пока разойдётся DNS.

**Нагрузка:** Caddy плюс «Пульс» помещаются в 1 ГБ.

!!! warning "Нужен домен"
    Без собственного имени сертификат получить нельзя. Если домена ещё нет — прочитайте лабораторию, продолжайте пользоваться адресом `http://IP:8080` и вернитесь позже.

**Перед стартом:** выполнена лаборатория 4, A-запись создана по инструкции из [урока про DNS](../modules/m05/01-dns-zapisi.md).

## Шаг 1. Убедиться, что имя указывает на ваш сервер

**Зачем:** это главное условие выдачи сертификата. Если пойти дальше с неверной записью, вы потратите попытки из недельного лимита.

**Где вводить:** PowerShell на вашем компьютере

```powershell
nslookup pulse.ваш-домен.ru
```

**Что должно получиться:** в ответе адрес, совпадающий с адресом сервера в панели хостера.

Если адрес другой или домен не найден — остановитесь здесь и дождитесь, пока запись разойдётся. Проверяйте раз в полчаса.

## Шаг 2. Проверить порты

**Зачем:** проверка владения идёт через порт 80, посетители приходят на 443. Нужны оба.

**Где вводить:** терминал сервера (`ssh ucheb`)

```bash
sudo ufw status
sudo ss -tulpn | grep ':80 '
```

**Что должно получиться:**

- в выводе `ufw status` есть строки `80/tcp ALLOW` и `443/tcp ALLOW`;
- вывод `ss` пустой, то есть порт 80 свободен.

Если портов нет в файрволе:

```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
```

Если порт 80 занят — найдите по выводу `ss`, какая программа его держит, и остановите её.

## Шаг 3. Скопировать файлы вахтёра на сервер

**Зачем:** нужны настройки Caddy и файл запуска, в котором описаны оба контейнера.

**Где вводить:** PowerShell на вашем компьютере, в папке курса

```powershell
scp .\labs\pulse\Caddyfile .\labs\pulse\compose.caddy.yml ucheb:/opt/pulse/
```

**Что должно получиться:** два имени файлов с индикатором прогресса.

## Шаг 4. Подставить своё имя в настройки

**Зачем:** в файле сейчас стоит пример, и по нему сертификат выдадут не вам.

**Где вводить:** терминал сервера

```bash
cd /opt/pulse
nano Caddyfile
```

Замените `pulse.example.ru` на ваше настоящее имя. Сохранение в nano: `Ctrl+O`, `Enter`, затем `Ctrl+X` для выхода.

**Что должно получиться:** проверьте результат:

```bash
cat Caddyfile
```

В первой строке блока должно стоять ваше имя — ровно то же, что вы проверяли на шаге 1. Сверьте посимвольно: одна опечатка означает сертификат на чужое имя и ошибку в браузере.

## Шаг 5. Запустить вахтёра

**Зачем:** Caddy встанет на порты 80 и 443, получит сертификат и начнёт передавать запросы «Пульсу» по внутренней сети.

**Где вводить:** терминал сервера

```bash
cd /opt/pulse
docker compose -f compose.caddy.yml up -d --build
```

Первый запуск занимает несколько минут: скачивается образ Caddy и идёт выпуск сертификата.

**Что должно получиться:** строки `Container pulse Started` и `Container caddy Started`.

Проверяем состояние:

```bash
docker compose -f compose.caddy.yml ps
```

**Что должно получиться:** оба контейнера в состоянии `Up`. У `caddy` в колонке портов видно `0.0.0.0:80->80/tcp` и `0.0.0.0:443->443/tcp`. У `pulse` публикации портов быть не должно.

## Шаг 6. Прочитать журнал и убедиться, что сертификат выдан

**Зачем:** это момент, где выясняется, всё ли правильно с именем и портами.

**Где вводить:** терминал сервера

```bash
docker compose -f compose.caddy.yml logs caddy --tail=80
```

**Что должно получиться:** строки со словами `certificate obtained` и `serving initial configuration`.

Если вместо этого повторяются ошибки, найдите свою в таблице:

| Что в журнале | Причина | Что делать |
|---|---|---|
| `no such host` | A-запись неверна или не разошлась | вернитесь к шагу 1 |
| `timeout during connect` | закрыт порт 80 | шаг 2, проверьте также файрвол хостера |
| `address already in use` | порт 80 занят | остановите занявшую его программу |
| `too many failed authorizations` | исчерпан лимит попыток | остановите Caddy и подождите неделю |

!!! danger "При ошибке останавливайте контейнер"
    Каждая повторная попытка тратит недельный лимит Let's Encrypt.

    ```bash
    docker compose -f compose.caddy.yml stop caddy
    ```

    Сначала чините причину, потом запускайте снова.

## Шаг 7. Открыть сайт в браузере

**Где смотреть:** браузер на вашем компьютере, адрес `https://pulse.ваш-домен.ru`.

**Что должно получиться:**

- страница «Пульс» открывается;
- в адресной строке замок без предупреждений;
- при нажатии на замок видно, что сертификат выдан Let's Encrypt и действует около трёх месяцев;
- заметка из лаборатории 4 на месте — данные не потерялись при пересоздании контейнеров.

## Шаг 8. Убедиться, что порт 8080 закрылся

**Зачем:** это половина смысла всей лаборатории. Наружу должен смотреть только вахтёр.

**Где вводить:** PowerShell на вашем компьютере

```powershell
curl http://203.0.113.10:8080/health
```

**Что должно получиться:** ошибка подключения. Отказ здесь — правильный результат.

Если ответ пришёл, значит, всё ещё работает старый набор контейнеров:

**Где вводить:** терминал сервера

```bash
docker ps -a
```

Оставить нужно только `caddy` и `pulse` из нового файла. Лишнее удалите:

```bash
docker rm -f имя_лишнего_контейнера
```

## Шаг 9. Проверить файрвол начисто

**Где вводить:** терминал сервера

```bash
sudo ufw status
```

**Что должно получиться:** в списке ровно 22, 80 и 443. Порта 8080 быть не должно. Если он есть:

```bash
sudo ufw delete allow 8080/tcp
```

## Шаг 10. Проверить перезагрузкой

**Зачем:** убедиться, что вся конструкция — приложение, вахтёр и сертификат — поднимается сама.

**Где вводить:** терминал сервера

```bash
sudo reboot
```

Подождите 2 минуты и откройте `https://pulse.ваш-домен.ru`.

**Что должно получиться:** страница открывается с замком, повторный выпуск сертификата не потребовался — Caddy взял его из сохранённой папки.

## Шаг 11. Записать результат

Добавьте в инвентарь:

- имя сайта и дату продления домена;
- пометку «сертификат обновляется автоматически»;
- дату, когда проверяли перезагрузку.

В [чеклисте продакшена](../checklists/production.md) можно отметить пункты про HTTPS и закрытые порты.

## Если что-то пошло не так

| Симптом | Вероятная причина |
|---|---|
| браузер ругается на имя в сертификате | в Caddyfile другое имя, чем в адресной строке (например, забыли `www`) |
| страница не открывается совсем | вспомогательный веб-сервер хостера занял порт 80 |
| открывается иногда | создана AAAA-запись, а IPv6 на сервере нет — удалите её |
| `8080` всё ещё отвечает | параллельно работает старый набор контейнеров, смотрите `docker ps -a` |

## Готово, если

- [ ] `https://ваше-имя` открывается с замком
- [ ] Сертификат выдан Let's Encrypt
- [ ] Обращение к `IP:8080` снаружи не проходит
- [ ] В файрволе только 22, 80 и 443
- [ ] После перезагрузки всё поднялось само
- [ ] Имя записано в инвентарь
