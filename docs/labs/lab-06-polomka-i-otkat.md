# Лаборатория 6. Поломка и откат данных

**Цель:** сделать копию заметки на компьютере, намеренно испортить данные на сервере, восстановить их из копии и увидеть прежний текст в браузере.

**Время:** 30–50 минут.

**Нагрузка:** влезает в 1 ГБ. Архив весит килобайты.

**Перед стартом:** «Пульс» работает после модулей 3–5, сайт открывается.

!!! info "Зачем ломать специально"
    Восстановление, которое вы делаете впервые в день аварии, обычно не получается. Сегодня спокойный день — самое время потренироваться.

## Шаг 1. Создать узнаваемую заметку

**Зачем:** нужен текст, который вы точно узнаете. «Тест» и «123» не годятся — их легко перепутать.

Откройте сайт в браузере и сохраните заметку:

```
лаборатория 6, до поломки
```

**Где вводить:** терминал сервера (`ssh ucheb`)

```bash
cat /opt/pulse/data/note.txt
```

**Что должно получиться:** ровно та строка, которую вы ввели в браузере. Если файла нет — заметка не сохранилась, разберитесь с правами: `sudo chown -R 10001:10001 /opt/pulse/data`.

## Шаг 2. Собрать архив

**Зачем:** превратить папку в один файл с датой в имени, чтобы копии не перетирали друг друга.

**Где вводить:** PowerShell на вашем компьютере, в папке курса

```powershell
scp .\labs\backup\backup-pulse.sh ucheb:/opt/pulse/
```

**Где вводить:** терминал сервера

```bash
chmod +x /opt/pulse/backup-pulse.sh
sh /opt/pulse/backup-pulse.sh
```

**Что должно получиться:** строка с путём к архиву вида `/tmp/pulse-data-20260925-1610.tgz`. Запишите это имя — оно понадобится дальше.

Проверяем содержимое, не распаковывая:

```bash
tar -tzf /tmp/pulse-data-*.tgz
```

**Что должно получиться:** две строки — `data/` и `data/note.txt`. Если списка нет, архив пустой и дальше идти бессмысленно.

## Шаг 3. Увезти архив на компьютер

**Зачем:** копия на том же сервере не спасает от смерти диска. Нужен другой носитель.

**Где вводить:** PowerShell на вашем компьютере (подставьте имя файла из шага 2)

```powershell
scp ucheb:/tmp/pulse-data-20260925-1610.tgz $env:USERPROFILE\Documents\
```

**Что должно получиться:** индикатор прогресса и `100%` в конце.

Откройте файл в «Документах» архиватором.

**Что должно получиться:** внутри видна папка `data` и файл `note.txt` с вашим текстом. Вот теперь это настоящая копия «не здесь».

Уберём временный файл с сервера:

**Где вводить:** терминал сервера

```bash
rm /tmp/pulse-data-*.tgz
```

## Шаг 4. Сломать данные намеренно

**Зачем:** воспроизвести аварию в управляемых условиях.

**Где вводить:** терминал сервера

```bash
cd /opt/pulse
sudo mv data data.broken
sudo mkdir data
sudo chown -R 10001:10001 data
echo "это уже не то" | sudo tee data/note.txt
sudo chown 10001:10001 data/note.txt
docker compose -f compose.caddy.yml restart
```

Что здесь происходит: настоящую папку отложили в сторону, на её место положили новую с посторонним текстом.

**Что должно получиться:** откройте сайт и обновите страницу сочетанием `Ctrl+F5` (без кэша). На странице — текст «это уже не то». Ваша заметка пропала.

!!! note "Почему мы не удалили папку совсем"
    Папка `data.broken` — страховка на случай, если что-то пошло не так с копированием на компьютер. В настоящей аварии её не будет, и единственной надеждой останется архив.

## Шаг 5. Вернуть архив на сервер

**Где вводить:** PowerShell на вашем компьютере (подставьте своё имя файла)

```powershell
scp $env:USERPROFILE\Documents\pulse-data-20260925-1610.tgz ucheb:/tmp/restore.tgz
```

**Что должно получиться:** `100%` в конце передачи.

## Шаг 6. Восстановить данные

**Зачем:** это и есть главный момент лаборатории.

**Где вводить:** терминал сервера

```bash
cd /opt/pulse
tar -tzf /tmp/restore.tgz
```

**Что должно получиться:** в списке есть `data/note.txt`. Только убедившись в этом, идём дальше.

```bash
sudo mv data data.oops
sudo tar -xzf /tmp/restore.tgz
sudo chown -R 10001:10001 data
cat data/note.txt
```

**Что должно получиться:** команда `cat` печатает `лаборатория 6, до поломки`.

Перезапускаем сервис:

```bash
docker compose -f compose.caddy.yml restart
```

**Что должно получиться:** в браузере после `Ctrl+F5` снова ваша исходная заметка. Это и есть критерий успеха — не «файл на месте», а знакомый текст на экране.

## Шаг 7. Убрать за собой

**Зачем:** на диске 10 ГБ, а мусор копится незаметно.

**Где вводить:** терминал сервера

```bash
rm /tmp/restore.tgz
sudo rm -rf /opt/pulse/data.oops /opt/pulse/data.broken
ls -la /opt/pulse
```

Удаляйте только **после** того, как убедились в браузере, что всё вернулось.

**Что должно получиться:** в папке остались файлы приложения и одна папка `data`.

## Шаг 8. Записать результат

Занесите в инвентарь:

- где лежит архив на компьютере;
- дату проверки восстановления;
- сколько минут заняло — это ваш реальный показатель времени восстановления.

В [чеклисте продакшена](../checklists/production.md) отметьте пункт «бэкап проверен восстановлением».

## Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| архив пустой, 0 байт | папка `data` была пуста | сохраните заметку и соберите архив заново |
| `Permission denied` при записи заметки | права после распаковки принадлежат `root` | `sudo chown -R 10001:10001 /opt/pulse/data` |
| в браузере старый текст, хотя файл новый | кэш браузера | обновите через `Ctrl+F5` |
| `scp` не находит файл | опечатка в имени с датой | скопируйте имя из вывода `ls /tmp` |

## Готово, если

- [ ] Архив открывается на компьютере и внутри видна заметка
- [ ] После намеренной поломки сайт показал посторонний текст
- [ ] После восстановления вернулась исходная заметка
- [ ] Временные файлы и лишние папки удалены
- [ ] В архиве нет файла `.env`
- [ ] Дата проверки записана в инвентарь

Теперь у вас есть не «бэкап», а проверенная копия. Разница между этими словами и есть содержание модуля 6.
