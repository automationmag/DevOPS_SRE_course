# Лаборатория 18. Песочница и «Пульс» на языке кластера

**Цель:** увидеть живой кластер вне учебного сервера и сопоставить кластерные описания с вашим `compose.yml`.

**Время:** 30–60 минут в зависимости от варианта.

**Нагрузка на учебный VPS:** нулевая. На сервер с одним гигабайтом мы не ставим ничего.

!!! danger "Что в этой лаборатории запрещено"
    - ставить кластер, даже облегчённый, на учебный сервер;
    - оставлять включённым платный арендованный кластер;
    - отправлять файл доступа к кластеру в репозиторий.

Выберите один из трёх вариантов. Любой из них засчитывается.

## Вариант А. Песочница в браузере

Подходит всем, ничего устанавливать не нужно.

### Шаг 1. Открыть площадку

**Где делать:** браузер на вашем компьютере.

Откройте [KillerCoda](https://killercoda.com/) и найдите сценарии по Kubernetes.

**Что должно получиться:** страница с бесплатным временным кластером. Если ссылка не работает, поищите «interactive kubernetes playground» и выберите площадку, где кластер выдаётся на время, а не оформляется подписка.

### Шаг 2. Пройти базовый сценарий

Возьмите сценарий про Pod и Deployment.

**Что должно получиться:** вы своими глазами видите, как появляется копия приложения и как она восстанавливается после удаления.

!!! warning "Команды площадки берите из площадки"
    Интерфейсы и версии меняются. Сценарий на сайте актуальнее любого текста в курсе.

### Шаг 3. Посмотреть список объектов

**Где вводить:** терминал внутри песочницы

```bash
kubectl get pods
```

**Что должно получиться:** таблица с копиями приложения и их состоянием. Это прямой аналог `docker compose ps`, к которому вы привыкли.

### Шаг 4. Удалить копию и посмотреть, что будет

**Где вводить:** терминал внутри песочницы

```bash
kubectl delete pod <имя из списка>
kubectl get pods
```

**Что должно получиться:** на месте удалённой копии появляется новая. Это и есть та самая автоматическая нянька, которой на одной машине заниматься нечем.

## Вариант Б. Локальный кластер на своём компьютере

Только если свободно не меньше 4 ГБ памяти и установлен Docker Desktop.

### Шаг 5. Установить инструмент

**Где вводить:** PowerShell на вашем компьютере

Следуйте актуальной инструкции с сайта kind. Версии меняются, поэтому команда установки в курсе не приводится.

**Что должно получиться:** команда `kind version` отвечает номером версии.

### Шаг 6. Создать кластер

**Где вводить:** PowerShell на вашем компьютере

```powershell
kind create cluster --name uchebnyy
```

**Что должно получиться:** сообщение об успешном создании. Обратите внимание, сколько памяти при этом заняло — это наглядный ответ на вопрос, почему кластер не ставят на учебный сервер.

### Шаг 7. Применить описания курса по очереди

**Где вводить:** PowerShell на вашем компьютере, в папке проекта

Порядок важен: сначала зона, потом настройки, потом само приложение.

```powershell
kubectl apply -f labs\k8s\namespace.yaml
kubectl apply -f labs\k8s\configmap.yaml
kubectl apply -f labs\k8s\secret.yaml
kubectl apply -f labs\k8s\pvc.yaml
kubectl apply -f labs\k8s\deployment.yaml
kubectl apply -f labs\k8s\service.yaml
```

**Что должно получиться:** на каждую команду ответ о создании объекта.

### Шаг 8. Проверить состояние

**Где вводить:** PowerShell на вашем компьютере

```powershell
kubectl -n pulse get pods
```

**Что должно получиться:** одна копия в рабочем состоянии. Если она не запускается — посмотрите подробности командой `kubectl -n pulse describe pod <имя>`, там будет причина.

### Шаг 9. Открыть сервис себе

**Где вводить:** PowerShell на вашем компьютере

```powershell
kubectl -n pulse port-forward svc/pulse 8080:8080
```

Оставьте окно открытым и в **новом** окне PowerShell выполните:

```powershell
curl.exe http://127.0.0.1:8080/health
```

**Что должно получиться:** знакомый ответ о состоянии. Это тот же «Пульс», просто запущенный кластером.

Такой проброс — аналог туннеля из модуля 14: порт открыт только вам, а не всему интернету.

### Шаг 10. Удалить кластер

**Где вводить:** PowerShell на вашем компьютере

```powershell
kind delete cluster --name uchebnyy
```

**Что должно получиться:** кластер удалён, память освободилась. Забытый учебный кластер ест память так же, как забытый сервер ест деньги.

## Вариант В. Только чтение

Если ни браузерная песочница, ни локальный кластер не получаются.

### Шаг 11. Разобрать описания построчно

**Где смотреть:** все файлы в папке `labs/k8s/` и пояснения в `labs/k8s/README.md`.

Для каждого файла ответьте на два вопроса: какая у объекта роль и что ему соответствует в `compose.yml`.

**Что должно получиться:** заполненная таблица соответствий без пропусков. Этого достаточно для зачёта лаборатории.

## Финальная часть для всех вариантов

### Шаг 12. Ответить на контрольные вопросы

1. Чем Deployment отличается от Service?
2. Зачем нужен Ingress и почему одного файла описания мало?
3. Почему при обычном диске копия обычно одна?
4. Что произойдёт, если проверка живости будет обращаться к тяжёлому адресу?
5. При каком условии вы вернётесь к теме кластера?

**Что должно получиться:** пять ответов своими словами. Последний — с числами из предыдущего урока.

## Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| Копия не запускается | нет диска или ошибка в описании | `kubectl -n pulse describe pod <имя>` — причина в конце вывода |
| Копия перезапускается по кругу | проверка живости не проходит | посмотреть логи: `kubectl -n pulse logs <имя>` |
| Проброс порта обрывается | окно закрыли или копию пересоздали | запустить проброс заново |
| Компьютер начал тормозить | локальный кластер съел память | удалить кластер, вернуться к варианту А |
| Площадка не открывается | сценарии и адреса меняются | взять другую песочницу либо вариант В |

## Готово, если

- [ ] Вы объясняете разницу между Deployment, Service и Ingress
- [ ] Знаете, почему копия одна при обычном диске
- [ ] Таблица соответствий с `compose.yml` заполнена
- [ ] Учебный сервер не тронут
- [ ] Учебный кластер, если создавали, удалён
- [ ] Файл доступа к кластеру не попал в репозиторий
