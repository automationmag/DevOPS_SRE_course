# Лаборатория 16. Заполнить инвентарь

**Цель:** превратить шаблон курса в вашу живую таблицу и проверить её главным тестом — попробовать восстановить доступ, пользуясь только ею.

**Время:** 30–40 минут.

**Нагрузка:** нулевая на сервер.

## Шаг 1. Сделать копию шаблона

**Зачем:** шаблон курса лежит в репозитории, и заполнять его своими данными нельзя.

**Где смотреть:** [шаблон инвентаря](../inventory-template.md).

Скопируйте структуру в облачную таблицу или в файл вне папки проекта.

**Что должно получиться:** пустая таблица с вашими разделами в месте, которое не синхронизируется с публичным репозиторием.

## Шаг 2. Записать серверы

**Зачем:** это первое, что забывается.

Заполните строку про учебный сервер:

| Поле | Пример того, что писать |
|---|---|
| Хостер | название и ссылка на панель |
| IP | адрес сервера |
| Тариф | 1 CPU / 1 ГБ / 10 ГБ |
| Пользователь для входа | `deploy` |
| Где ключ | запись в менеджере паролей |
| Дата оплаты | число месяца |

**Что должно получиться:** строка, по которой вы войдёте на сервер через полгода.

!!! warning "Строка «где ключ» — это ссылка, не ключ"
    Пишем, в какой записи менеджера паролей лежит ключ. Само содержимое ключа в таблицу не переносим.

## Шаг 3. Записать домен

**Зачем:** домен и его записи — вторая по частоте причина «почему не работает».

Заполните:

- имя домена;
- у какого регистратора;
- включено ли автопродление;
- дата окончания;
- какие записи DNS настроены и куда указывают.

**Что должно получиться:** блок, по которому понятно, куда идти, если домен перестал открываться.

Если домена нет, напишите явно «нет». Пустая ячейка выглядит как забытая, явное «нет» — как решение.

## Шаг 4. Перечислить секреты по именам

**Зачем:** чтобы при уходе человека или подозрении на утечку было что отзывать.

Список того, что обычно есть к этому моменту:

1. Ключ SSH для сервера.
2. Доступ в панель хостера.
3. Доступ к регистратору домена.
4. Токен Telegram-бота.
5. Файл `/opt/pulse/.env` на сервере.
6. Файл `/opt/pulse/alert.env` на сервере.
7. Секреты репозитория для автоматической выкладки.

**Что должно получиться:** семь строк вида «что это — где лежит». Значений нет ни в одной.

## Шаг 5. Записать резервные копии

**Зачем:** без этой строки копии есть, но найти их некому.

Заполните:

- где лежат копии;
- как часто создаются;
- дата последней проверки восстановления.

**Что должно получиться:** конкретная дата в последней строке либо честное «ни разу не проверяла». Второе — тоже полезная запись, она подсказывает, что делать.

## Шаг 6. Перенести счёт и даты

**Зачем:** свести результаты первых двух уроков модуля.

Добавьте:

- итоговую сумму в месяц;
- на какой адрес приходят письма хостера;
- четыре даты из календаря.

**Что должно получиться:** денежный раздел, который отвечает на вопрос «сколько стоит проект» без похода по кабинетам.

## Шаг 7. Записать людей и доступы

**Зачем:** продолжение модуля 14.

Строки:

| Кто | Какой доступ | Когда выдан |
|---|---|---|
| вы | полный | |
| учебный пользователь, если был | и отозван ли | |
| ключ для автоматической выкладки | только выкладка | |

**Что должно получиться:** список, по которому можно пройтись при отзыве доступа.

## Шаг 8. Главная проверка — закрыть панель хостера

**Зачем:** это тест на то, живая таблица или мёртвая.

Закройте панель хостера и, глядя только в инвентарь, ответьте:

1. Какой IP у сервера и под каким пользователем входить?
2. Где лежит ключ?
3. Куда уезжают копии и когда их проверяли?
4. Когда следующая оплата?
5. Кому выдан доступ, кроме вас?

**Что должно получиться:** пять ответов без догадок. Если хоть на один ответить не удалось — вернитесь и дозаполните. Это и есть смысл лаборатории.

## Шаг 9. Убедиться, что таблица не попала в git

**Где вводить:** PowerShell на вашем компьютере, в папке проекта

```powershell
git status
```

**Что должно получиться:** в списке изменений нет вашего файла инвентаря. Если он там есть — переместите таблицу за пределы папки проекта.

## Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| Не могу заполнить «где ключ» | ключ лежит просто в папке на компьютере | завести менеджер паролей и перенести |
| Дата проверки копии пустая | восстановление ни разу не проверяли | вернуться к лаборатории 6 |
| Файл инвентаря виден в `git status` | таблица создана внутри папки проекта | переместить наружу |
| Не помню, кому выдавала доступ | нет истории | посмотреть `/home/*/.ssh/authorized_keys` на сервере |

## Готово, если

- [ ] Есть единственная главная копия вне публичного репозитория
- [ ] В ячейках нет паролей и ключей
- [ ] Заполнены серверы, домен, секреты по именам, копии, счёт, люди
- [ ] Дата сверки резервной копии проставлена или честно помечена как отсутствующая
- [ ] Вы ответили на пять вопросов шага 8 без панели хостера
- [ ] `git status` не показывает файл инвентаря
