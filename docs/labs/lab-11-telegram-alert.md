# Лаборатория 11. Алерт в Telegram

**Цель:** получить сообщение в телефон, когда сайт перестал отвечать, и второе — когда он снова ожил.

**Время:** 40–60 минут.

**Нагрузка:** влезает в 1 ГБ. n8n на этот сервер не ставим.

**Перед стартом:** бот создан в BotFather, вы отправили ему `/start`, знаете номер чата. Токен сохранён в менеджере паролей.

## Шаг 1. Положить секреты на сервер

**Зачем:** скрипту нужны токен, номер чата и адрес проверки. В самом скрипте их держать нельзя.

**Где вводить:** PowerShell на вашем компьютере, в папке курса

```powershell
scp .\labs\alerts\check-pulse.sh ucheb:/opt/pulse/
scp .\labs\alerts\alert.env.example ucheb:/opt/pulse/
```

**Где вводить:** терминал сервера (`ssh ucheb`)

```bash
cd /opt/pulse
cp alert.env.example alert.env
chmod 600 alert.env
chmod +x check-pulse.sh
nano alert.env
```

Заполните три значения:

- токен бота;
- номер чата;
- адрес проверки — тот же, по которому ходят люди: `https://pulse.ваш-домен.ru/health`. Если вы ещё на IP, используйте `http://127.0.0.1:8080/health`.

**Что должно получиться:** проверьте права:

```bash
ls -la alert.env check-pulse.sh
```

- у `alert.env` права `-rw-------`;
- у `check-pulse.sh` есть признак исполняемого файла (`-rwx`).

## Шаг 2. Проверить доставку сообщений

**Зачем:** убедиться, что бот вообще может вам написать, до того как встраивать его в автоматику.

**Где вводить:** терминал сервера

```bash
set -a; . /opt/pulse/alert.env; set +a
curl -s "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendMessage" \
  --data-urlencode "chat_id=${TELEGRAM_CHAT_ID}" \
  --data-urlencode "text=проверка связи, лаборатория 11"
echo
```

Первая строка загружает значения из файла в окружение текущей сессии.

**Что должно получиться:**

- в терминале ответ, начинающийся с `{"ok":true`;
- в Telegram сообщение «проверка связи, лаборатория 11».

Если пришёл `{"ok":false`, смотрите описание ошибки:

| Ошибка | Причина |
|---|---|
| `Unauthorized` | неверный токен |
| `chat not found` | неверный номер чата или не было `/start` |
| `Bad Request: message text is empty` | не подставились переменные из файла |

## Шаг 3. Прогнать скрипт при живом сайте

**Зачем:** увидеть, что в нормальном состоянии скрипт молчит. Это правильное поведение — сообщения приходят только при смене состояния.

**Где вводить:** терминал сервера

```bash
sh /opt/pulse/check-pulse.sh
echo "код возврата: $?"
```

**Что должно получиться:**

- код возврата `0`;
- в Telegram тихо.

Тишина здесь означает «всё в порядке», а не «скрипт не работает» — работу вы проверили на шаге 2.

## Шаг 4. Устроить учебное падение

**Зачем:** главная проверка лаборатории.

**Где вводить:** терминал сервера

```bash
cd /opt/pulse
docker compose -f compose.caddy.yml stop pulse
sh /opt/pulse/check-pulse.sh
```

**Что должно получиться:** в Telegram пришло сообщение о том, что проверка не отвечает.

Теперь запустите скрипт ещё раз:

```bash
sh /opt/pulse/check-pulse.sh
```

**Что должно получиться:** второго сообщения **нет**. Скрипт запомнил, что уже сообщал. Именно эта защита не даёт превратить одну поломку в сто уведомлений за ночь.

Посмотрите, где хранится память о состоянии:

```bash
ls -la /opt/pulse/alert-state/
```

**Что должно получиться:** файл с пометкой о том, что сигнал уже отправлен.

## Шаг 5. Вернуть сервис и получить второе сообщение

**Зачем:** уведомление о восстановлении не менее важно — без него вы не знаете, можно ли расслабиться.

**Где вводить:** терминал сервера

```bash
docker compose -f compose.caddy.yml start pulse
sleep 3
sh /opt/pulse/check-pulse.sh
```

**Что должно получиться:** в Telegram сообщение о том, что сервис снова отвечает.

## Шаг 6. Поставить проверку на расписание

**Зачем:** до сих пор вы запускали скрипт руками. Теперь пусть это делает система.

**Где вводить:** терминал сервера

```bash
crontab -e
```

Если редактор спросит, какой использовать, выберите `nano`.

Добавьте строку в конец файла:

```
*/2 * * * * /bin/sh /opt/pulse/check-pulse.sh >> /opt/pulse/alert-state/cron.log 2>&1
```

Читается так: каждые две минуты запускать скрипт, а вывод дописывать в файл журнала.

Сохраните (`Ctrl+O`, `Enter`) и выйдите (`Ctrl+X`).

**Что должно получиться:** проверьте, что запись принята:

```bash
crontab -l
```

**Что должно получиться:** ваша строка в списке.

!!! danger "Токен в расписание не вписывают"
    Список заданий читается проще, чем кажется. Все значения должны оставаться в файле `alert.env` с правами 600.

## Шаг 7. Проверить, что расписание работает

**Зачем:** запись в списке заданий ещё не означает, что скрипт запускается.

**Где вводить:** терминал сервера

Подождите 4–5 минут и посмотрите:

```bash
tail -20 /opt/pulse/alert-state/cron.log
date
```

**Что должно получиться:** в журнале есть записи, а их время близко к текущему.

Если журнал пустой:

| Причина | Что делать |
|---|---|
| нет прав на выполнение | `chmod +x /opt/pulse/check-pulse.sh` |
| папки `alert-state` не существует | `mkdir -p /opt/pulse/alert-state` |
| опечатка в пути | сверьте путь в `crontab -l` |

## Шаг 8. Финальная проверка целиком

**Зачем:** убедиться, что цепочка работает без вашего участия.

**Где вводить:** терминал сервера

```bash
cd /opt/pulse
docker compose -f compose.caddy.yml stop pulse
```

Ничего больше не делайте и подождите до трёх минут.

**Что должно получиться:** сообщение в Telegram придёт само, без запуска скрипта руками. Это и есть цель модуля 11.

Возвращаем:

```bash
docker compose -f compose.caddy.yml start pulse
```

**Что должно получиться:** в течение двух минут придёт уведомление о восстановлении.

## Шаг 9. Записать в инвентарь

Отметьте:

- сигнал «сайт не отвечает» переведён в автоматический;
- периодичность проверки — 2 минуты;
- куда приходят сообщения.

В [чеклисте продакшена](../checklists/production.md) отметьте пункт про уведомление о недоступности.
