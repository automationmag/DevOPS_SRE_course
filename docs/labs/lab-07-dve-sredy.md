# Лаборатория 7. Два .env без путаницы

**Цель:** убедиться на практике, что поведение «Пульса» задаётся переменными среды, а не кодом, и завести разные наборы значений для рабочего окружения и репетиции.

**Время:** 25–40 минут.

**Нагрузка:** влезает в 1 ГБ. Второй набор контейнеров на сервере не поднимаем.

**Перед стартом:** «Пульс» работает, файл `.env` на сервере существует.

## Шаг 1. Проверить, что заголовок не зашит в код

**Зачем:** если значение прописано прямо в Python, никакие файлы среды его не изменят. Это первое, что стоит проверить.

**Где вводить:** терминал сервера (`ssh ucheb`)

```bash
grep PULSE_TITLE /opt/pulse/app.py /opt/pulse/compose.yml /opt/pulse/.env
```

**Что должно получиться:** три группы строк:

- в `app.py` — только чтение переменной из окружения, без вашего заголовка в кавычках;
- в `compose.yml` — строка `env_file` или упоминание переменной;
- в `.env` — текущее значение.

Если в `app.py` заголовок написан текстом — это как раз та ошибка, от которой избавляет модуль 7.

## Шаг 2. Сохранить текущее состояние

**Зачем:** чтобы гарантированно вернуть рабочий вариант после эксперимента.

**Где вводить:** терминал сервера

```bash
cd /opt/pulse
cp .env .env.bak
ls -la .env*
```

**Что должно получиться:** рядом появился файл `.env.bak`.

## Шаг 3. Поменять только значение переменной

**Где вводить:** терминал сервера

```bash
nano /opt/pulse/.env
```

Поставьте `PULSE_TITLE=Пульс-лаборатория-7`. Сохранение: `Ctrl+O`, `Enter`, выход `Ctrl+X`.

Применяем:

```bash
cd /opt/pulse
docker compose -f compose.caddy.yml up -d --force-recreate
```

Если вы ещё не проходили модуль 5 и работаете без Caddy, используйте `docker compose up -d --force-recreate`.

**Что должно получиться:** строка `Container pulse Recreated` или `Started`.

## Шаг 4. Убедиться, что значение дошло

**Где вводить:** терминал сервера

```bash
docker compose -f compose.caddy.yml exec pulse env | grep PULSE_TITLE
```

**Что должно получиться:** `PULSE_TITLE=Пульс-лаборатория-7`.

Теперь откройте сайт в браузере и обновите страницу через `Ctrl+F5`.

**Что должно получиться:** новый заголовок на странице. Файл `app.py` при этом вы не трогали — в этом весь смысл упражнения.

## Шаг 5. Проверить, что код действительно не менялся

**Зачем:** зафиксировать вывод: изменилось поведение, не код.

**Где вводить:** терминал сервера

```bash
ls -la /opt/pulse/app.py
```

**Что должно получиться:** дата изменения файла — та, когда вы его копировали, а не сегодняшняя.

## Шаг 6. Вернуть рабочее значение

**Зачем:** эксперимент закончен, сайт должен выглядеть как положено.

**Где вводить:** терминал сервера

```bash
cd /opt/pulse
cp .env.bak .env
chmod 600 .env
docker compose -f compose.caddy.yml up -d --force-recreate
rm .env.bak
ls -la .env
```

**Что должно получиться:**

- в браузере прежний заголовок;
- права у `.env` — `-rw-------`;
- файла `.env.bak` больше нет.

## Шаг 7. Завести набор значений для репетиции

**Зачем:** чтобы репетиционное окружение с первого взгляда отличалось от рабочего.

**Где вводить:** PowerShell на вашем компьютере, в папке курса

```powershell
cd .\labs\pulse
copy .env.example .env
```

Впишите в него `PULSE_TITLE=Репетиция`.

**Что должно получиться:** локальный файл со значением, отличным от серверного. Теперь по заголовку вы всегда понимаете, где находитесь.

## Шаг 8. Убедиться, что секреты не попадут в репозиторий

**Где вводить:** PowerShell на вашем компьютере, в корне папки курса

```powershell
git check-ignore -v .env
git check-ignore -v labs/pulse/.env
```

Команда `git check-ignore` отвечает, игнорируется ли файл, и показывает строку правила.

**Что должно получиться:** для каждого файла строка с указанием на `.gitignore`. Если вывод пустой — файл **не** игнорируется, и его легко случайно добавить. Исправьте список исключений.

Дополнительная проверка:

```powershell
git status
```

**Что должно получиться:** файлов `.env` в списке нет.

## Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| заголовок не изменился | контейнер не пересоздан | добавьте `--force-recreate` |
| переменной нет в `exec env` | в файле запуска нет `env_file: .env` | добавьте строку и повторите |
| значение пустое | переменная переопределена в разделе `environment:` | уберите её оттуда |
| `git check-ignore` молчит | файл не в исключениях | добавьте `.env` в `.gitignore` |

## Готово, если

- [ ] Заголовок менялся без единой правки в Python
- [ ] Вы видели переменную внутри работающего контейнера
- [ ] Рабочее значение возвращено, права 600 на месте
- [ ] Заведён отдельный набор значений для репетиции
- [ ] Оба файла `.env` игнорируются репозиторием
- [ ] В инвентаре записано, где живёт репетиция: на компьютере или её пока нет
