# Лаборатория 17. Защита диплома себе

**Цель:** пройти чеклист с доказательствами и зафиксировать два адреса — сервиса и учебника.

**Время:** 40–60 минут.

**Нагрузка:** одна перезагрузка сервера и одна короткая остановка сервиса. Новых тяжёлых программ не ставим.

!!! info "Правило этой лаборатории"
    Галочка ставится после того, как вы что-то показали. Не до и не «по памяти».

## Часть А. Сервис

### Шаг 1. Вход на сервер

**Зачем:** проверить, что дверь закрыта правильно.

**Где вводить:** терминал сервера (`ssh ucheb`)

```bash
sudo grep -E "PermitRootLogin|PasswordAuthentication" /etc/ssh/sshd_config
```

**Что должно получиться:** обе строки со значением `no`. Вход возможен только по ключу и не под root.

### Шаг 2. Файрвол и пользователь

**Где вводить:** терминал сервера (`ssh ucheb`)

```bash
whoami && sudo ufw status
```

**Что должно получиться:** имя обычного пользователя (не `root`) и список из нескольких разрешённых портов — обычно 22, 80 и 443.

### Шаг 3. Автоподъём после перезагрузки

**Зачем:** главная проверка самостоятельности сервиса.

**Где делать:** панель хостера, перезагрузка сервера.

Через две-три минуты откройте адрес сервиса в браузере.

**Что должно получиться:** сайт отвечает сам. Вы не заходили на сервер и ничего не запускали.

!!! warning "Если пришлось запускать руками"
    Значит, в `compose.yml` нет политики перезапуска. Возвращайтесь к модулю 4 — этот пункт блокирующий.

### Шаг 4. Секреты вне репозитория

**Где вводить:** PowerShell на вашем компьютере, в папке проекта

```powershell
git check-ignore -v .env
```

**Что должно получиться:** строка с указанием, какое правило игнорирует файл. Пустой ответ означает, что файл может уехать в репозиторий.

### Шаг 5. Копии и проверенное восстановление

**Где смотреть:** папка с архивами на компьютере и инвентарь.

**Что должно получиться:** свежий архив с датой и запись о том, когда восстановление проверялось на практике. Без второго пункта галочка не ставится.

### Шаг 6. Адрес состояния

**Где вводить:** терминал сервера (`ssh ucheb`)

```bash
curl -s http://127.0.0.1:8080/health
```

**Что должно получиться:** короткий ответ о состоянии сервиса.

### Шаг 7. Защищённое соединение

Откройте сервис в браузере по домену.

**Что должно получиться:** замок в адресной строке. Если домена пока нет — ставьте отметку «пока по IP» честно, без самообмана.

### Шаг 8. Логи

**Где вводить:** терминал сервера (`ssh ucheb`)

```bash
cd /opt/pulse && docker compose logs --tail=20
```

**Что должно получиться:** последние двадцать строк. Важно не содержимое, а то, что вы знаете эту команду без подсказки.

### Шаг 9. Сигнал о сбое

**Где вводить:** терминал сервера (`ssh ucheb`)

```bash
cd /opt/pulse && docker compose stop
```

Подождите несколько минут, дождитесь сообщения, затем верните:

```bash
docker compose start && sleep 5 && curl -s http://127.0.0.1:8080/health
```

**Что должно получиться:** сообщение в Telegram во время остановки и нормальный ответ сервиса после запуска.

Если сигналов вы не настраивали — отметка «нет» и строка в списке задач.

### Шаг 10. Показатель надёжности

**Где смотреть:** инвентарь.

**Что должно получиться:** записанная цель вроде 99% в месяц и понимание, сколько минут простоя это допускает.

## Часть Б. Учебник

### Шаг 11. Локальная сборка

**Где вводить:** PowerShell на вашем компьютере, в папке проекта, окружение активировано

```powershell
mkdocs build --strict
```

**Что должно получиться:** сборка без ошибок.

### Шаг 12. Публичный адрес

Откройте адрес учебника.

**Что должно получиться:** сайт открывается. Либо адрес на GitHub Pages, либо своя раздача за паролем.

### Шаг 13. Чтение с телефона

Откройте с телефона в инкогнито, желательно через мобильный интернет.

**Что должно получиться:** оглавление читается, ссылки работают.

## Часть В. Порядок

### Шаг 14. Инвентарь

**Что должно получиться:** таблица заполнена и в ней есть оба адреса — сервиса и учебника.

### Шаг 15. Календарь оплат

**Что должно получиться:** четыре напоминания из модуля 16 стоят на месте.

### Шаг 16. Отзыв доступа

**Зачем:** проверить, что при необходимости вы сможете закрыть доступ быстро.

Опишите словами, что будете делать: какие ключи убирать, какие пароли менять, какие секреты отзывать.

**Что должно получиться:** последовательность из нескольких пунктов, а не «разберусь по ходу».

### Шаг 17. Список того, что осталось красным

Напишите себе несколько строк: что не сделано и что из этого не стыдно отложить.

Обычно в этот список попадают Kubernetes, облака и приём платежей. Все три — темы понимания, а не установки на учебный сервер.

**Что должно получиться:** короткий честный список. Это ваш план после курса.

## Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| После перезагрузки сервис не поднялся | нет политики перезапуска в `compose.yml` | модуль 4, урок про автоподъём |
| `git check-ignore` молчит | файл не в списке игнорируемых | добавить `.env` в `.gitignore` |
| Сборка падает в строгом режиме | битая ссылка в тексте | читать сообщение, оно указывает файл |
| Сигнал не пришёл | задание в планировщике не работает | лаборатория 11, проверить `cron.log` |
| Нет даты проверки восстановления | восстановление не проверяли | лаборатория 6, это блокирующий пункт |

## Готово, если

- [ ] Вход по ключу, root запрещён
- [ ] Файрвол настроен, работаете не под root
- [ ] Сервис пережил перезагрузку самостоятельно
- [ ] Секреты не уходят в репозиторий
- [ ] Есть копия и дата проверенного восстановления
- [ ] Адрес состояния отвечает
- [ ] Защищённое соединение либо честная отметка «пока по IP»
- [ ] Вы знаете, где смотреть логи
- [ ] Сигнал о сбое проверен либо отмечен как отсутствующий
- [ ] Показатель надёжности записан
- [ ] Учебник собирается и открывается с телефона
- [ ] Инвентарь живой, календарь заполнен, порядок отзыва доступа описан
