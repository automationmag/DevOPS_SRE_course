# Лаборатория 14. Второй пользователь и полный отзыв

**Цель:** завести учебную учётную запись с ограниченными правами, убедиться, что она действительно слабее вашей, и снять её так, как если бы человек ушёл.

**Время:** 30–40 минут.

**Нагрузка:** влезает в 1 ГБ.

!!! warning "Работаем отдельным ключом"
    Не используйте свой рабочий ключ для учебной учётной записи. Весь смысл упражнения в том, что ключи разные.

**Перед стартом:** вы заходите на сервер как `deploy`, прошли модуль 14.

## Шаг 1. Создать отдельный ключ

**Зачем:** у каждого человека свой ключ. Именно это позволяет потом отозвать доступ у одного, не трогая остальных.

**Где вводить:** PowerShell на вашем компьютере

```powershell
ssh-keygen -t ed25519 -C "trainee-ucheb" -f $env:USERPROFILE\.ssh\id_ed25519_trainee
```

На вопрос о пароле нажмите `Enter` дважды — это учебный ключ.

**Что должно получиться:** два файла и картинка из символов. Смотрим публичную часть:

```powershell
Get-Content $env:USERPROFILE\.ssh\id_ed25519_trainee.pub
```

**Что должно получиться:** одна длинная строка, начинающаяся с `ssh-ed25519` и заканчивающаяся на `trainee-ucheb`. Скопируйте её целиком.

## Шаг 2. Создать пользователя на сервере

**Где вводить:** терминал сервера (`ssh ucheb`)

```bash
sudo adduser trainee
```

Система спросит пароль — придумайте любой, он не понадобится для входа по ключу. Остальные вопросы можно пропустить клавишей `Enter`.

**Что должно получиться:** сообщение о создании пользователя и домашней папки.

!!! danger "В группы sudo и docker не добавляем"
    Это принципиально. Группа `docker` по возможностям равна правам администратора, а мы создаём именно ограниченную учётную запись.

## Шаг 3. Положить публичный ключ

**Где вводить:** терминал сервера

```bash
sudo mkdir -p /home/trainee/.ssh
sudo nano /home/trainee/.ssh/authorized_keys
```

Вставьте скопированную строку из шага 1. Сохранение: `Ctrl+O`, `Enter`, выход `Ctrl+X`.

Теперь права:

```bash
sudo chown -R trainee:trainee /home/trainee/.ssh
sudo chmod 700 /home/trainee/.ssh
sudo chmod 600 /home/trainee/.ssh/authorized_keys
ls -la /home/trainee/.ssh
```

**Что должно получиться:**

- папка `.ssh` с правами `drwx------`;
- файл `authorized_keys` с правами `-rw-------`;
- владелец у обоих — `trainee`.

Если права шире, SSH откажется принимать ключ и не объяснит почему.

## Шаг 4. Проверить вход

**Зачем:** убедиться, что доступ работает, до того как проверять его ограниченность.

**Где вводить:** новое окно PowerShell на вашем компьютере (подставьте свой адрес)

```powershell
ssh -i $env:USERPROFILE\.ssh\id_ed25519_trainee trainee@203.0.113.10
```

**Что должно получиться:** приглашение вида `trainee@vps:~$`.

Если не пускает, смотрите шаг 3 — почти всегда дело в правах на файлы.

## Шаг 5. Убедиться, что прав действительно меньше

**Зачем:** это главная проверка лаборатории. Учётная запись должна быть бессильной.

**Где вводить:** терминал сервера, **от имени trainee**

```bash
whoami
```

**Что должно получиться:** `trainee`.

```bash
sudo whoami
```

**Что должно получиться:** сообщение `trainee is not in the sudoers file` — отказ. Это успех.

```bash
docker ps
```

**Что должно получиться:** `permission denied while trying to connect to the Docker daemon socket`. Тоже успех.

```bash
cat /opt/pulse/.env
```

**Что должно получиться:** `Permission denied`. Секреты недоступны, как и задумано.

```bash
ls /opt/pulse
```

**Что должно получиться:** список файлов виден — чтение папки разрешено. Это нормально: мы ограничивали изменение, а не просмотр.

Выходим:

```bash
exit
```

## Шаг 6. Убедиться, что ваш доступ не пострадал

**Где вводить:** PowerShell на вашем компьютере

```powershell
ssh ucheb
```

**Где вводить:** терминал сервера

```bash
whoami
sudo whoami
docker ps --format '{{.Names}}'
```

**Что должно получиться:** `deploy`, затем `root`, затем список контейнеров. Ваши права на месте.

## Шаг 7. Отозвать доступ

**Зачем:** отработать процедуру ухода человека.

Есть два варианта, и разницу между ними надо понимать.

**Вариант А — снять только ключ, оставив учётную запись:**

```bash
sudo rm /home/trainee/.ssh/authorized_keys
```

Подходит, когда человек может вернуться.

**Вариант Б — удалить полностью:**

```bash
sudo deluser --remove-home trainee
```

Подходит, когда сотрудничество закончено. Домашняя папка удаляется вместе с пользователем.

Для лаборатории выберите вариант Б.

**Что должно получиться:** сообщение об удалении пользователя и его файлов.

## Шаг 8. Проверить, что отзыв сработал

**Зачем:** без этого шага вы не знаете, закрыт доступ или нет. Именно его чаще всего пропускают.

**Где вводить:** PowerShell на вашем компьютере

```powershell
ssh -i $env:USERPROFILE\.ssh\id_ed25519_trainee trainee@203.0.113.10
```

**Что должно получиться:** `Permission denied (publickey)`. Отказ — это правильный результат.

## Шаг 9. Убрать учебный ключ и записать результат

**Где вводить:** PowerShell на вашем компьютере

```powershell
Remove-Item $env:USERPROFILE\.ssh\id_ed25519_trainee*
```

Запишите в инвентарь: «учебная учётная запись trainee заведена и отозвана такого-то числа, отзыв проверен».

Заодно перечитайте [чеклист ухода](../modules/m14/03-uhod-cheloveka.md) и отметьте, какие из восьми пунктов вы теперь умеете выполнять.

## Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| ключ не принимается при входе | слишком широкие права на `.ssh` | шаг 3, права 700 и 600 |
| `sudo whoami` сработал | пользователь попал в группу sudo | `sudo deluser trainee sudo` |
| `docker ps` сработал | пользователь в группе docker | `sudo deluser trainee docker` |
| после удаления вход всё равно проходит | ключ остался где-то ещё | `sudo find /home -name authorized_keys` |

## Готово, если

- [ ] Учебная учётная запись входила своим отдельным ключом
- [ ] Административные команды ей были недоступны
- [ ] Секреты в `.env` прочитать не удалось
- [ ] Ваш собственный доступ не пострадал
- [ ] После отзыва вход не проходит, и вы это проверили
- [ ] Учебный ключ удалён с компьютера, запись в инвентаре есть
