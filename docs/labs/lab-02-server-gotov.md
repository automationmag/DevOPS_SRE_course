# Лаборатория 2. Сервер можно использовать

**Цель:** закрыть базовый контур безопасности до установки Docker и убедиться, что всё работает.

**Время:** 30–50 минут.

**Нагрузка:** влезает в 1 ГБ.

**Перед стартом:** выполнена лаборатория 1, вы заходите командой `ssh ucheb` под пользователем `deploy`.

Эта лаборатория в основном повторяет то, что вы уже делали в уроках модуля 2 — но здесь всё собрано в один проход с проверками. Если какой-то шаг уже выполнен, просто убедитесь, что проверка проходит.

## Шаг 1. Проверить, кто вы

**Зачем:** все дальнейшие шаги рассчитаны на обычного пользователя с правом `sudo`.

**Где вводить:** терминал сервера

```bash
whoami
```

**Что должно получиться:** `deploy`. Если `root` — зайдите через `ssh ucheb`.

## Шаг 2. Обновить систему

**Зачем:** закрыть известные дыры до того, как сервер начнёт что-то обслуживать.

**Где вводить:** терминал сервера

```bash
sudo apt update
sudo apt upgrade -y
sudo apt autoremove -y
sudo apt clean
```

**Что должно получиться:** установка завершается без ошибок. Если в списке обновлённых пакетов было что-то со словом `linux-image`, выполните перезагрузку:

```bash
sudo reboot
```

Через минуту зайдите снова: `ssh ucheb`.

## Шаг 3. Настроить файрвол

**Зачем:** снаружи должны быть доступны только нужные двери.

**Где вводить:** терминал сервера

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
```

На вопрос о возможном обрыве соединения ответьте `y`.

**Что должно получиться:** `Firewall is active and enabled on system startup`.

### Обязательная проверка

**Где вводить:** PowerShell на вашем компьютере, **новое** окно

```powershell
ssh ucheb
```

**Что должно получиться:** вход проходит. Если нет — в старом окне выполните `sudo ufw disable` и разберитесь с правилами, прежде чем идти дальше.

Итоговый список правил:

```bash
sudo ufw status numbered
```

**Что должно получиться:** `Status: active` и три правила — OpenSSH, 80, 443. Ничего лишнего.

## Шаг 4. Поставить fail2ban

**Зачем:** ограничить тех, кто перебирает пароли в разрешённую дверь SSH.

**Где вводить:** терминал сервера

```bash
sudo apt install -y fail2ban
sudo systemctl enable --now fail2ban
sudo fail2ban-client status sshd
```

**Что должно получиться:** блок с информацией о правиле `sshd`, включая счётчики попыток. Ошибка `NOK: ('sshd',)` означает, что правило не включено — как это исправить, написано в [уроке про файрвол](../modules/m02/02-firewall-fail2ban.md), шаг 8.

## Шаг 5. Включить swap, если его нет

**Зачем:** на 1 ГБ памяти swap не даёт системе зависнуть при всплеске нагрузки.

**Где вводить:** терминал сервера

```bash
free -h
```

**Что должно получиться:** строка `Swap`. Если там `0B` — выполните команды со [страницы про учебный VPS](../lab-server.md) и проверьте снова.

## Шаг 6. Подготовить папку приложения

**Зачем:** к модулю 3 нужно готовое место с правильным владельцем.

**Где вводить:** терминал сервера

```bash
sudo mkdir -p /opt/pulse
sudo chown deploy:deploy /opt/pulse
ls -ld /opt/pulse
```

**Что должно получиться:** строка, в которой дважды написано `deploy` — владелец и группа.

Проверим, что работать можно без `sudo`:

```bash
touch /opt/pulse/test.txt && rm /opt/pulse/test.txt && echo "права в порядке"
```

**Что должно получиться:** надпись `права в порядке`. Если вместо этого `Permission denied` — вернитесь к команде `chown` выше.

## Шаг 7. Проверить состояние сервера целиком

**Зачем:** зафиксировать исходную точку. Дальше на сервере появится Docker, и полезно знать, сколько ресурсов было свободно до него.

**Где вводить:** терминал сервера

```bash
df -h /
free -h
uptime
```

**Что должно получиться и что записать в инвентарь:**

- `df -h /` — сколько процентов диска занято сейчас (обычно 15–30%);
- `free -h` — сколько памяти доступно в колонке `available` (обычно 600–800 МБ);
- `uptime` — время работы с последней перезагрузки.

## Шаг 8. Навести порядок в панели хостера

**Зачем:** доступ в панель равен доступу к серверу.

Действия в браузере, команд нет:

- [ ] включить двухфакторную защиту в профиле;
- [ ] проверить, что вы знаете, где кнопка перезагрузки;
- [ ] проверить, что знаете, где аварийная консоль;
- [ ] посмотреть дату следующего списания.

## Готово, если

- [ ] Вход только под `deploy` и только по ключу
- [ ] `ssh root@адрес` отказывает
- [ ] `sudo ufw status` — active, ровно три правила
- [ ] `sudo fail2ban-client status sshd` отвечает без ошибки
- [ ] `free -h` показывает ненулевой Swap
- [ ] Диск занят меньше чем на 80%
- [ ] Папка `/opt/pulse` принадлежит `deploy`
- [ ] В панели хостера включена двухфакторная защита
- [ ] В инвентарь записаны адрес, пользователь, путь к ключу, дата оплаты

Если хотя бы один пункт не закрыт — не переходите к Docker. Он не решит эти проблемы, он их умножит: дырявое приложение станет доступно из интернета.

Далее: [Зачем нужен контейнер](../modules/m03/01-zachem-docker.md).
