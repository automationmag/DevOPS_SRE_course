# Лаборатория 3. Упаковать «Пульс» в Docker

**Цель:** поставить Docker, перенести учебное приложение на сервер, собрать образ и получить ответ «я жив» с самого сервера.

**Время:** 40–80 минут, основное время занимает скачивание.

**Нагрузка:** влезает в 1 ГБ. Базовый образ Python весит несколько сотен мегабайт — это разовая трата диска.

**Перед стартом:** выполнена лаборатория 2, вы заходите под `deploy`, папка `/opt/pulse` существует и принадлежит вам.

## Шаг 1. Подготовить хранилище пакетов Docker

**Зачем:** Docker ставится не из стандартного набора Ubuntu, а из собственного хранилища компании. Сначала нужно добавить его ключ и адрес.

**Где вводить:** терминал сервера (`ssh ucheb`)

```bash
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
```

**Что должно получиться:** команды отрабатывают молча или с обычным выводом установки пакетов. Проверим, что ключ на месте:

```bash
ls -l /etc/apt/keyrings/docker.asc
```

**Что должно получиться:** строка с файлом размером в несколько килобайт. Если файла нет — скорее всего, не было доступа к сайту Docker, смотрите раздел с ошибками внизу.

## Шаг 2. Добавить адрес хранилища

**Зачем:** сказать системе, откуда брать пакеты Docker для вашей версии Ubuntu.

**Где вводить:** терминал сервера

```bash
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update
```

Команда сама подставит кодовое имя вашей версии Ubuntu.

**Что должно получиться:** в выводе `apt update` появится строка со словом `download.docker.com`. Ошибок быть не должно.

## Шаг 3. Установить Docker

**Где вводить:** терминал сервера

```bash
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

**Что должно получиться:** установка нескольких пакетов, в конце — возврат к приглашению. Проверяем:

```bash
sudo systemctl status docker
```

**Что должно получиться:** строка `Active: active (running)`. Выйти — клавиша `q`.

## Шаг 4. Разрешить работу без sudo

**Зачем:** чтобы не писать `sudo` перед каждой командой Docker.

**Где вводить:** терминал сервера

```bash
sudo usermod -aG docker deploy
```

!!! warning "Обязательно перезайдите"
    Новая группа применяется только при новом входе. Выполните `exit`, затем снова `ssh ucheb`. Без этого следующий шаг выдаст ошибку прав доступа.

Проверяем после перезахода:

```bash
docker version
docker compose version
```

**Что должно получиться:** две пары строк — версия клиента и версия сервера, затем версия Compose.

Если видите `permission denied while trying to connect to the Docker daemon socket` — вы не перезашли на сервер. Выполните `exit` и войдите снова.

## Шаг 5. Перенести файлы приложения на сервер

**Зачем:** приложение и файлы запуска лежат в репозитории курса на вашем компьютере, их нужно скопировать на сервер.

**Где вводить:** PowerShell на вашем компьютере, в папке курса

```powershell
scp -r .\labs\pulse\* ucheb:/opt/pulse/
```

Короткое имя `ucheb` работает благодаря файлу настроек из лаборатории 1.

**Что должно получиться:** список скопированных файлов с индикатором прогресса: `app.py`, `Dockerfile`, `compose.yml`, `.env.example`, `.dockerignore`.

Проверяем на сервере:

**Где вводить:** терминал сервера

```bash
ls -la /opt/pulse
```

**Что должно получиться:** перечисленные выше файлы, владелец `deploy`.

Если `scp` не сработал, создайте файлы вручную через `nano`, копируя содержимое из репозитория.

## Шаг 6. Подготовить переменные и папку данных

**Зачем:** приложению нужен файл с настройками и папка, куда оно будет сохранять заметку.

**Где вводить:** терминал сервера

```bash
cd /opt/pulse
cp .env.example .env
chmod 600 .env
mkdir -p data
sudo chown -R 10001:10001 data
ls -la
```

Что здесь происходит:

- копируем образец переменных в рабочий файл;
- закрываем его от посторонних;
- создаём папку для данных;
- передаём её пользователю с номером 10001 — именно под этим номером приложение работает внутри контейнера. Без этого шага заметка не сохранится.

**Что должно получиться:** в списке файлов должны быть строки:

- `-rw------- 1 deploy deploy ... .env` — права только у владельца;
- `drwxr-xr-x 2 10001 10001 ... data` — папка принадлежит пользователю контейнера.

## Шаг 7. Собрать и запустить

**Зачем:** превратить рецепт в образ и запустить контейнер.

**Где вводить:** терминал сервера

```bash
cd /opt/pulse
docker compose up -d --build
```

Первый запуск идёт несколько минут: скачивается базовый образ Python. Не запускайте вторую сборку параллельно — памяти не хватит.

**Что должно получиться:** строки загрузки слоёв, затем `Container pulse Started`.

Проверяем состояние:

```bash
docker compose ps
```

**Что должно получиться:** таблица, где в колонке `STATUS` написано `Up` и время работы. Если там `Exited` или `Restarting` — смотрите шаг 9.

## Шаг 8. Проверить, что приложение отвечает

**Зачем:** убедиться, что дело не только в запущенном процессе, но и в рабочем ответе.

**Где вводить:** терминал сервера

```bash
curl -s http://127.0.0.1:8080/health
```

**Что должно получиться:** ответ `{"status":"ok"}`.

Напомню: `127.0.0.1` означает «этот же компьютер», то есть сам сервер. Из браузера на вашем ноутбуке этот адрес открывать бесполезно — сайт по внешнему адресу мы откроем в следующей лаборатории.

Смотрим журнал:

```bash
docker compose logs --tail=30
```

**Что должно получиться:** строка вида `pulse listening on 0.0.0.0:8080`.

## Шаг 9. Если контейнер не запустился

**Где вводить:** терминал сервера

```bash
docker compose logs --tail=50
```

Читайте последние строки — там причина. Частые варианты:

| Что в журнале | Что делать |
|---|---|
| `Permission denied: '/data/note.txt'` | не выполнен `chown` из шага 6 |
| `port is already allocated` | порт 8080 занят другим контейнером: `docker ps -a` |
| `no space left on device` | кончился диск, смотрите [карточку про диск](../runbooks/disk-full.md) |
| ошибка Python с именем файла | файлы скопировались не полностью, повторите шаг 5 |

## Шаг 10. Проверить расход ресурсов

**Зачем:** зафиксировать, сколько теперь занято, и убедиться, что лимит работает.

**Где вводить:** терминал сервера

```bash
docker stats --no-stream
free -h
df -h /
```

**Что должно получиться:**

- в `docker stats` колонка `MEM USAGE / LIMIT` показывает что-то вроде `12MiB / 64MiB` — лимит применился;
- в `free -h` колонка `available` не нулевая, обычно осталось 400–600 МБ;
- в `df -h /` занято больше, чем до установки: образ Python занял место.

Запишите эти три числа в инвентарь — пригодятся для сравнения, когда что-то пойдёт не так.

## Готово, если

- [ ] `docker version` работает без `sudo`
- [ ] `docker compose ps` показывает статус `Up`
- [ ] `curl http://127.0.0.1:8080/health` отвечает `{"status":"ok"}`
- [ ] В журнале есть строка про прослушивание порта
- [ ] Лимит памяти виден в `docker stats`
- [ ] Папка `data` принадлежит пользователю 10001

Приложение работает, но увидеть его из браузера пока нельзя: наружу порт не открыт. Этим займёмся в следующем модуле.
