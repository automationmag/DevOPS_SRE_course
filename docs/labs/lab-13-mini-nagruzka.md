# Лаборатория 13. Осторожный мини-тест

**Цель:** посмотреть, как «Пульс» отвечает на небольшую серию запросов, и не уронить при этом учебный сервер.

**Время:** 20–30 минут.

!!! danger "Эту лабораторию легко превратить в аварию"
    Три правила, которые нельзя нарушать:

    - **не запускайте тест с самого сервера** — программа для теста съест ту же память, которую вы измеряете;
    - **не берите примеры из статей** с тысячей одновременных соединений — они рассчитаны на другое железо;
    - **не увеличивайте нагрузку**, если уже на пятом запросе появились задержки.

    Если SSH перестал отвечать: панель хостера → перезагрузка, затем `free -h` и проверка на нехватку памяти.

**Перед стартом:** сайт работает, вы прошли модуль 13.

## Шаг 1. Убедиться, что запас памяти есть

**Зачем:** если памяти в обрез, тест её добьёт. Это единственный шаг, после которого можно остановиться и не делать лабораторию.

**Где вводить:** терминал сервера (`ssh ucheb`)

```bash
free -h
df -h /
docker stats --no-stream
```

**Что должно получиться:** значение в колонке `available`.

| Сколько свободно | Что делать |
|---|---|
| больше 300 МБ | можно продолжать |
| 150–300 МБ | продолжайте, но следите за шагом 4 |
| меньше 150 МБ | **лабораторию не делайте**, сначала разгрузите машину |

Запишите три числа: свободную память, занятость диска и расход контейнера.

## Шаг 2. Открыть второе окно для наблюдения

**Зачем:** смотреть за сервером во время теста нужно в реальном времени, а не после.

**Где вводить:** второе окно PowerShell на вашем компьютере

```powershell
ssh ucheb
```

Оставьте это окно открытым. В нём вы будете выполнять команды наблюдения.

**Что должно получиться:** два независимых подключения. Тест пойдёт с компьютера, наблюдение — в этом окне.

## Шаг 3. Двадцать спокойных запросов

**Зачем:** двадцать — достаточно, чтобы увидеть тенденцию, и мало, чтобы навредить.

**Где вводить:** первое окно PowerShell на вашем компьютере (подставьте свой адрес)

```powershell
1..20 | ForEach-Object {
  $t = Measure-Command {
    Invoke-WebRequest -Uri "https://pulse.ваш-домен.ru/health" -UseBasicParsing | Out-Null
  }
  "{0,2}: {1:N0} мс" -f $_, $t.TotalMilliseconds
}
```

**Что должно получиться:** двадцать строк с номером и временем в миллисекундах.

Как это читать:

| Картина | Вывод |
|---|---|
| все числа примерно одинаковые | сервер спокойно держит такую нагрузку |
| числа растут от первого к последнему | что-то накапливается, смотрите шаг 4 |
| зависание на середине | **остановите тест**, идите в логи |

!!! tip "Если PowerShell ругается на синтаксис"
    Просто обновите страницу `/health` в браузере двадцать раз и следите, не растёт ли задержка. Результат будет грубее, но вывод тот же.

## Шаг 4. Посмотреть на сервер во время теста

**Зачем:** цифры времени ответа сами по себе не объясняют причину.

**Где вводить:** второе окно (то, что с сервером), пока идёт тест

```bash
docker stats --no-stream
free -h
uptime
```

**Что должно получиться:**

- расход памяти контейнером остался в пределах лимита 64 МБ;
- свободная память не обнулилась;
- в конце вывода `uptime` три числа средней загрузки — на одном ядре значение около 1,0 означает полную занятость процессора.

!!! warning "Если свободная память обнулилась"
    Вы вышли за рамки лаборатории. Прекратите тест, перезагрузите сервер и на сегодня закончите. Ничего страшного не произошло — вы узнали свой потолок.

## Шаг 5. Проверить, что сервер цел

**Зачем:** главный результат этой лаборатории — сервер остался живым.

**Где вводить:** терминал сервера

```bash
docker compose -f compose.caddy.yml ps
curl -s https://pulse.ваш-домен.ru/health
sudo dmesg -T | grep -i "out of memory" | tail -5
```

**Что должно получиться:**

- контейнеры в состоянии `Up`;
- ответ `{"status":"ok"}`;
- пустой вывод последней команды — нехватки памяти не было.

Если последняя команда что-то показала, значит, система кого-то остановила. Это ценная информация: вы нашли свой предел.

## Шаг 6. Сделать вывод, а не рекорд

**Зачем:** цель лаборатории — не число для резюме, а понимание своего сервера.

Запишите в инвентарь четыре пункта:

1. Обычное время ответа — столько-то миллисекунд.
2. Что изменилось в памяти во время теста.
3. Что стало бы узким местом первым, если бы нагрузка выросла.
4. Что **не** нужно делать в ответ на такую нагрузку (менять тариф вслепую, ставить кластер).

**Что должно получиться:** четыре строки, к которым можно вернуться через полгода.

## Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| SSH перестал отвечать | кончилась память | перезагрузка из панели хостера |
| Время ответа выросло в разы | процессор занят | снизьте число запросов, смотрите `uptime` |
| `Invoke-WebRequest` ругается на сертификат | адрес указан с опечаткой | сверьте имя домена |
| Контейнер перезапустился | превышен лимит памяти | `docker compose logs pulse --tail=30` |

## Готово, если

- [ ] Проверили запас памяти **до** теста
- [ ] Сделали не больше двадцати лёгких запросов
- [ ] Наблюдали за сервером во время теста во втором окне
- [ ] SSH после теста жив, сайт отвечает
- [ ] Записали четыре вывода
- [ ] Не устанавливали на сервер нагрузочные программы

Главное умение этой лаборатории — вовремя остановиться. Оно пригодится чаще, чем умение выжать максимум.
