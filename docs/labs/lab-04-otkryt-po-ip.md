# Лаборатория 4. Открыть «Пульс» по IP

**Цель:** увидеть учебный сайт в браузере по адресу `http://ВАШ_IP:8080`, сохранить заметку и убедиться, что всё переживает перезагрузку.

**Время:** 30–45 минут.

**Нагрузка:** влезает в 1 ГБ. Порт 8080 временно открыт в интернет — это учебная мера, в модуле 5 мы её уберём.

**Перед стартом:** выполнена лаборатория 3, контейнер запущен, `curl` с сервера отвечает.

## Шаг 1. Убедиться, что приложение работает изнутри

**Зачем:** если не отвечает даже сам себе, снаружи тем более не ответит. Начинаем с ближнего слоя.

**Где вводить:** терминал сервера (`ssh ucheb`)

```bash
cd /opt/pulse
docker compose ps
curl -s http://127.0.0.1:8080/health
```

**Что должно получиться:**

- в `docker compose ps` статус `Up`;
- `curl` печатает `{"status":"ok"}`.

Если здесь уже проблема — дальше не идите, разберитесь по [каталогу отказов](../modules/m04/04-oshibki-deploy.md).

## Шаг 2. Убедиться, что порт опубликован наружу

**Зачем:** проверить, что дверь на сервере действительно есть.

**Где вводить:** терминал сервера

```bash
docker compose ps
sudo ss -tulpn | grep 8080
```

**Что должно получиться:**

- в колонке `PORTS` строка `0.0.0.0:8080->8080/tcp`;
- в выводе `ss` строка с `0.0.0.0:8080` и процессом `docker-proxy`.

Если там `127.0.0.1:8080` — порт виден только самому серверу. Поправьте публикацию в `compose.yml` на `"8080:8080"` и выполните `docker compose up -d`.

## Шаг 3. Узнать свой публичный адрес

**Зачем:** нужен точный адрес, по которому вы будете стучаться из браузера.

**Где вводить:** терминал сервера

```bash
curl -s ifconfig.me
echo
```

**Что должно получиться:** четыре числа через точку, например `203.0.113.10`. Они должны совпадать с адресом в панели хостера. Запишите этот адрес.

## Шаг 4. Проверить из PowerShell

**Зачем:** проверка из командной строки даёт понятную ошибку, а браузер часто просто показывает «страница недоступна».

**Где вводить:** PowerShell на вашем компьютере (подставьте свой адрес)

```powershell
curl http://203.0.113.10:8080/health
```

**Что должно получиться:** в выводе будет `{"status":"ok"}`.

Если не получилось:

| Что видите | Причина | Что делать |
|---|---|---|
| долго ждёт, потом ошибка | закрыт файрвол хостера | проверьте сетевые правила в панели хостера |
| `Connection refused` | приложение слушает только внутри | шаг 2 |
| `Could not resolve host` | опечатка в адресе | проверьте адрес из шага 3 |

## Шаг 5. Открыть в браузере

**Где вводить:** адресная строка браузера на вашем компьютере

```
http://203.0.113.10:8080
```

Три вещи, которые легко перепутать:

- именно `http`, а не `https` — сертификата ещё нет;
- обязательно с `:8080` — без порта на сервере никто не отвечает;
- ваш адрес, а не пример из инструкции.

**Что должно получиться:** страница с заголовком «Пульс» и зелёной строкой «Сервис жив».

!!! warning "Браузер может настаивать на https"
    Современные браузеры любят автоматически подставлять `https://`. Если видите ошибку сертификата, напишите адрес полностью, начиная с `http://`, или откройте страницу в режиме инкогнито.

## Шаг 6. Сохранить заметку и проверить, что она легла на диск

**Зачем:** это проверка того, что данные действительно пишутся в папку сервера, а не живут внутри контейнера.

В браузере введите в поле текст `лаборатория 4` и сохраните.

**Где вводить:** терминал сервера

```bash
cat /opt/pulse/data/note.txt
```

**Что должно получиться:** та же строка, которую вы ввели в браузере.

Если файл пустой или его нет — приложению не хватило прав на запись:

```bash
sudo chown -R 10001:10001 /opt/pulse/data
docker compose restart
```

## Шаг 7. Пережить перезагрузку

**Зачем:** настоящая проверка автоподъёма. Настройки из модуля 4 должны сработать без вашего участия.

**Где вводить:** терминал сервера

```bash
sudo reboot
```

Подождите 2 минуты, затем откройте `http://ВАШ_IP:8080` в браузере.

**Что должно получиться:**

- страница открывается;
- заметка «лаборатория 4» на месте;
- `docker compose ps` показывает `Up` со временем работы в пару минут.

Если контейнер не поднялся, проверьте автозапуск:

```bash
sudo systemctl is-enabled docker
docker inspect pulse --format '{{ .HostConfig.RestartPolicy.Name }}'
```

Должно быть `enabled` и `unless-stopped`.

## Шаг 8. Учебная поломка

**Зачем:** увидеть, как выглядит «сайт лежит», в спокойной обстановке.

**Где вводить:** терминал сервера

```bash
cd /opt/pulse
docker compose stop
```

Обновите страницу в браузере.

**Что должно получиться:** браузер показывает ошибку подключения. При этом `docker compose ps` показывает `Exited`, а в журнале нет ошибок — потому что ошибки и не было, вы остановили сервис сами.

Возвращаем:

```bash
docker compose start
```

Обновите браузер — страница снова открывается.

Запомните ход мысли: сломан был слой «процесс». Не DNS, не сертификат, не код. Именно с этого слоя стоит начинать в следующий раз.

## Шаг 9. Записать результат

Добавьте в инвентарь:

- адрес учебного сайта: `http://ВАШ_IP:8080`;
- пометка «учебный, не продакшен, порт закроем в модуле 5»;
- дата, когда проверяли перезагрузку.

В [чеклисте продакшена](../checklists/production.md) можно отметить пункт про автоматический подъём после перезагрузки.

## Готово, если

- [ ] Страница открывается с компьютера, а не только через SSH
- [ ] Заметка сохранилась в файл на сервере
- [ ] После перезагрузки всё поднялось само
- [ ] Вы один раз намеренно сломали и починили сервис
- [ ] Понимаете, что открытый 8080 — временная мера

Сайт работает, но адрес выглядит как набор цифр, а браузер честно пишет «не защищено». Дальше — домен и замочек.

Далее: [DNS-записи](../modules/m05/01-dns-zapisi.md).
