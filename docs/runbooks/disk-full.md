# Runbook: диск кончается

**Сигнал:** сайт тормозит, новые образы не скачиваются, в `df -h` раздел `/` больше 85%. На 10 ГБ это случится раньше, чем вы ожидаете.

## Почему так

Ubuntu + Docker + несколько старых образов + логи = шкаф забит. Docker по умолчанию копит слои образов.

## Что сделать

1. Посмотреть, чем занято:

```bash
df -h
sudo du -h -d 1 /var/lib/docker 2>/dev/null
```

2. Удалить неиспользуемые образы и кэш — **только** если все нужные контейнеры сейчас запущены или вы готовы скачать образ заново:

```bash
docker system df
docker system prune
```

`prune` без `-a` не трогает образы, которые ещё нужны запущенным контейнерам. Не делайте `prune -a --volumes` вслепую: можно снести данные.

3. Логи журнала системы:

```bash
sudo journalctl --disk-usage
sudo journalctl --vacuum-size=50M
```

4. Если диск 100% и даже команда не пишется — в панели хостера иногда есть «восстановление / увеличение диска». На тарифе 10 ГБ надёжнее почистить, чем надеяться на чудо.

## Как не повторить

- Один учебный стек, не пять копий «на пробу».
- Раз в месяц `docker system df`.
- Алерт «диск > 85%» появится в модуле 11. Пока — глазами.

**Влезает в 1 ГБ / 10 ГБ:** да, это как раз ваша реальность.
